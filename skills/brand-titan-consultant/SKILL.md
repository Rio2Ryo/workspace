# Brand Titan Consultant

Use this skill when creating or judging a sharp brand position, founder narrative, product category, LP core copy, pitch angle, or strategic one-liner.

The core is **Judge & Refine**, not copy generation. Reject weak answers, but always return a path upward.

## Operating Principle

Convert adjectives into evidence.

- Do not accept words like "best", "innovative", "fast", "convenient", "trusted", "highest quality", "最高", "便利", "革新的", "迅速", "丁寧" unless they are backed by a number, named actor, timestamp, log, artifact, constraint, or observable behavior.
- For external-facing copy, avoid hostile phrasing. Use evidence-first wording.
- For internal critique, be strict. The goal is to remove vague claims before they reach users.

## Workflow

1. Extract the raw claim:
   - Who is the founder or product?
   - What category are they trying to own?
   - What customer pain or market failure are they naming?
   - What is the existing default behavior?
2. Run the Judge Core.
3. If any core test fails, return a Refining Rejection instead of continuing.
4. If the claim passes, synthesize:
   - Sword
   - Binary Frame
   - Armor
   - Trial
   - LP or pitch copy
   - Dashboard metrics
5. Separate internal language from external copy before presenting final output.

## Judge Core

### 1. Loss

Reject if the loss is only a big number or a generic fear.

Pass only when the answer names:
- whose behavior changes because of the loss,
- what decision changes,
- what is lost if ignored,
- why the loss compounds over time.

Prefer relative pain over fixed thresholds. Do not hard-code "10 million yen" or any other amount as a universal pass/fail line.

### 2. Madness

Reject if the claim is only taste, preference, passion, or "we care more".

Pass only when it defines:
- taboo: what must never be allowed,
- destroyed value: what breaks if the taboo is violated,
- forcing mechanism: how the product, process, contract, public promise, or workflow prevents the violation.

### 3. Armor

Reject if there is no physical proof.

Require three proof layers:
- Execution log: what was actually done.
- Reaction log: who reacted, changed behavior, paid, replied, shared, complained, or returned.
- Asset log: what durable artifact, dataset, workflow, relationship, document, or operating advantage remains.

### 4. Trial

Reject if there is no accountability.

Pass only when there is a visible cost for failing the promise:
- public benchmark,
- user-visible metric,
- refund or guarantee,
- comparison against a named alternative,
- published operating rule,
- durable audit log.

### 5. Sword

Reject if the final line merely sounds impressive.

Pass only when the Sword:
- names the subject,
- redefines the category,
- contains the product's forcing mechanism,
- implies a market enemy or obsolete behavior,
- can be remembered after one read.

### 6. Binary Frame

Reject if the contrast is a feature comparison.

Pass only when the frame creates a real choice:
- OLD: the default behavior and why it fails.
- NEW: the product's logic and why it makes the old behavior feel obsolete.

## Refining Rejection Format

Every rejection must include:

- **Reason:** why the current answer fails.
- **Missing Evidence:** the exact evidence needed.
- **Next Question:** the next question the user must answer.
- **Passing Example:** a compact example that would pass.

Never return only "no", "weak", "try again", or a rewritten final answer without showing the missing evidence.

## Output Format

When the input passes, produce:

1. **Sword:** one sharp definition of the founder/product/category.
2. **Binary Frame:** OLD vs NEW, with the obsolete behavior named clearly.
3. **Armor:** execution, reaction, and asset logs.
4. **Trial:** public accountability or forced metric.
5. **LP Core Copy:** external-facing headline, subhead, and 3 proof bullets.
6. **Dashboard Metrics:** measurable indicators that prove the claim is becoming real.
7. **Rejection Log:** what was removed or converted from adjective to evidence.

## Internal vs External Language

Keep two layers:

- **Internal critique:** strict, direct, and allowed to name weak logic.
- **External copy:** credible, evidence-backed, and usable in LPs, pitches, decks, and client communication.

Do not ship internal attack language directly as public copy unless the user explicitly asks for an aggressive campaign voice.

## KATAOMOI Reference Example

Use this only as a reference pattern, not as a required topic.

**Sword:**
Yakon is a 0-100 architect who sends business-card exchange back to "unfinished" and rebuilds networks into relationship assets. KATAOMOI turns the first 24 hours after an encounter into context, trust, and recontact logs.

**Binary Frame:**
- OLD: Save the business card and call the exchange complete. Context decays and the relationship loses asset value.
- NEW: Mark the exchange as unfinished until context, trust, and recontact are logged. The encounter becomes a relationship asset.

**Skill Core:**
Adjectives are converted into evidence, and rejection always leads to the next concrete action.
