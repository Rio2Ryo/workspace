## FaceNet / vls-system incident and recovery notes
- vls-system thread: existing HF Space `ryosukematsuura-face-test-0409.hf.space` returned 404; InsightFace path depended on that HF Space while face-api.js path was independent.
- Face E2E root cause was missing admin auth + CSRF in tests, not missing implementation. After adding `x-admin-password`, `x-csrf-token`, and `csrf_token` cookie handling, face E2E passed.
- Admin and user-flow Playwright E2E suites were largely repaired by updating stale selectors/wording, login helper retries, locale assumptions, and strict-mode collisions. Reported end state reached full pass on current suite (103 passed / 0 failed) in-thread.
- Event status feature was added with statuses: 準備中 / 開催中 / 終了 / アーカイブ. Important safety rule learned: default for unset/new events should be 準備中, not 開催中, to avoid accidental public exposure.
- Dangerous incident: status/data updates and reset actions caused event photo metadata loss; summer festival photo metadata had to be reconstructed from R2. Durable lesson: before touching production-like event data, do backup first, avoid destructive UI controls, and verify dry-run/impact scope before DB writes.
- Test data cleanup removed many E2E-created events/companies while retaining demo data. Deletion work on shared/demo-like environments must list targets explicitly and preserve non-test fixtures.
- Summer 2026 login issue: admin view showed password `SUMMER2026`; actual access failure was more likely caused by event status/public-side logic than wrong password. Setting event status to 開催中 restored access.
- Email sending diagnosis for vls-system: `RESEND_API_KEY` existed but `EMAIL_FROM` was missing. Codebase expects envs like `RESEND_API_KEY` and `EMAIL_FROM`; likely mail failure root cause was missing sender env / sender verification, not absence of mail feature.
- Security lesson: never echo sensitive API keys back into chat; if a key is exposed in conversation, recommend rotation after troubleshooting.
