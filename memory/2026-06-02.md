## Sora-VPS2 Hermes / Gemini quota 429 復旧

- 何が起きたか: `#real-estate-investment-decision-app` で Sora-VPS2 が `Gemini HTTP 429 (RESOURCE_EXHAUSTED)` を連発し、Yakonさんの「再検証して」にも応答生成できなかった。
- なぜ起きたか: `/root/.hermes/config.yaml` が `provider: gemini` / `default: gemini-3-flash-preview` 一本で、`fallback_providers` も空だった。Gemini quota exhausted により通常応答だけでなく自動圧縮・watchdog cronも失敗していた。
- 対応: Sora-VPS2へSSHし、`/root/.hermes/config.yaml` をバックアップ後、`provider: openai-codex` / `default: gpt-5.4` / `base_url: ""` に変更。`/root/.local/bin/hermes -z "Reply with exactly: ok" --provider openai-codex -m gpt-5.4 --ignore-rules` で単体疎通OKを確認し、`sora-hermes` tmuxセッションだけを再起動した。
- 確認結果: 再起動後 `Connected as Sora-VPS2#5856`、`Gateway running with 1 platform(s)` を確認。ログ上で `provider=openai-codex model=gpt-5.4` の API call が複数回成功した。
- 次回どう防ぐか: Sora-VPS2で `RESOURCE_EXHAUSTED` が出た場合、Gemini再試行を続けず、まず `/root/.hermes/config.yaml` のproviderとfallback設定を確認する。Gemini quotaが原因なら、単体 `hermes -z` 疎通確認後に `openai-codex/gpt-5.4` へ切り替えて `sora-hermes` のみ再起動する。

## OpenClaw GPT-5.5 モデル解決の注意

- 何が起きたか: OpenClaw起動時に primary を `openai-codex/gpt-5.5` にしていると、モデル解決が `unknown` 扱いになり、fallback候補の `gpt-5.4` に落ちる表示が出た。
