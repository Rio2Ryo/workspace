## Ao-VPS / gotoさんからのメンション不応答
- 何が起きたか: gotoさんが `#kataomoi-ao` で `@Ao-VPS hi` してもAo-VPSが反応せず、Yakonさんから「私以外の人がメンションしても反応するように」と再依頼あり。
- 確認: Ao-VPS (`ao`, `163.44.122.214`) では通常応答経路は `/etc/systemd/system/hermes-gateway.service` の Hermes gateway。`/root/.hermes/.env` には `DISCORD_ALLOW_ALL_USERS=true` があったが、systemd service が同envを読み込んでおらず、プロセス環境に `DISCORD_ALLOW_ALL_USERS` が無かった。
- 対応: `/etc/systemd/system/hermes-gateway.service.d/10-discord-access.conf` を追加し、`DISCORD_ALLOW_ALL_USERS=true`, `DISCORD_ALLOWED_USERS=`, `DISCORD_ALLOWED_CHANNELS=1510493395246780516`, `DISCORD_REQUIRE_MENTION=true`, `DISCORD_THREAD_REQUIRE_MENTION=true`, `DISCORD_ALLOW_BOTS=mentions` を明示。`systemctl daemon-reload && systemctl restart hermes-gateway.service` 実行。
- 確認: 再起動後、Hermes gateway は `running` / Discord `connected`。プロセス環境にも上記 `DISCORD_*` が反映済み。
- 残リスク: gotoさん本人からの再メンション実機確認は未実施。Ao-VPS側の別プロセス `openclaw-gateway.service` はDiscord token 401、`discord-channel-monitor` は TokenInvalid で再起動ループしているが、今回の通常返信経路はHermes。

## Panai / Mazavege 応答停止
- 何が起きたか: Yakonさんから `#claude-hp改修(co.jp)` で Mazavege が落ちていると連絡。`@Mazavege` への応答なし、Panai tmux feed の trycloudflare URL は解決不可、`ssh panai` は banner timeout / reset。
- 原因確定: Azure VM `panai` は当初 running だったが、`/var/log/auth.log` に `beginning MaxStartups throttling` と `drop connection #10` があり、SSH全公開に対する外部preauth接続でsshdが詰まっていた。OpenClaw側も stale session lock を検出していたが、画像大量投入そのものが一次原因とはログ上確定できず。
- 対応: Azure CLIで `panai` を deallocate/start して復旧。`gateway ready`、`Discord bot probe resolved @Mazavege`、`openclaw agent --agent main --message "Reply with OK only."` が `OK` を返すことを確認。
- 恒久対策: Azure NSG `panaiNSG/default-allow-ssh` の source を `*` から現在の接続元 `217.178.131.245/32` に変更し、SSH全公開を停止。Panai側 `AGENTS.md` に「画像は原則3枚まで先に処理、4枚以上または合計10MB超は分割確認」を追記。
- 次回どう防ぐか: Mazavege/Panaiが無応答なら、最初に `az vm get-instance-view -g KATAOMOI -n panai`、NSG、`ssh -vvv panai`、`/var/log/auth.log` の MaxStartups を確認する。添付多数の依頼は同時処理せず、先頭3枚単位で進める。
