## Shiro Loop digest 報告形式の再修正
- 何が起きたか: Yakonより「報告内容がかわっていないよ？」と指摘。前回は報告方針を述べたが、`shiro-loop-digest` の実際の出力は `permission-wait` や分類カウント中心のままで、Yakonが何を確認すべきか先頭で分からなかった。
- なぜ起きたか: 方針を運用文面へ落としただけで、定時digestの生成スクリプトに「確認事項 / 推奨 / 白の次アクション」の構造を実装していなかった。
- 次回どう防ぐか: 定時・進捗・完了候補の報告は、人間向けの先頭文 `humanMessage` を生成元データに含める。未精製の承認待ちはYakonに投げず、白が先に承認パケットへ整理する。
- ルール反映: `ops/shiro-loop-digest.mjs` に `reportLabel / humanMessage / yakonQuestions / shiroActions / verifierMismatch` を追加。次回digestは「Yakon確認が必要か」「白が先に何をするか」を先頭に出す。

## Sora実回答なし問題
- 何が起きたか: `#real-estate-investment-decision-app` でSora-VPS2が質問に対してチェック反応や作業ログは出すが、本文回答を返さない状態が継続。やまざきさんより「確実に直しましょう。まずそこが最初」と指摘。
- なぜ起きたか: 白の前回指示文 `@Sora-VPS2` がDiscord実メンションになっておらず、message read上でも mentions が空だった。Sora側には明示メンション指示として届いていない可能性が高い。加えてSora側の挙動は「受信/反応」と「本文回答」が分離しており、進捗ログだけで完了扱いになっている。
- 次回どう防ぐか: Director AIや他botへ行動修正を依頼する時は、表示名ではなく必ず数値ID形式の `<@1469652850740035615>` などを使う。本文では「まず本文で回答」「ツールログだけで終えない」「最終回答必須」を明示する。
- ルール反映: Sora-VPS2の明示IDは `<@1469652850740035615>`。このスレッドでSoraに実指示する場合は表示名 `@Sora-VPS2` ではなく数値IDメンションを使う。

## Sora Discord認可設定による無反応
- 何が起きたか: やまざきさんが `#real-estate-investment-decision-app` で `@Sora-VPS2` に質問しても、Soraが本文回答しない状態が再発した。
- なぜ起きたか: Sora VPSの `/root/.hermes/logs/sora-hermes-gateway.log` に `Unauthorized user: 891164004070867014 (やまざき) on discord` が出ており、プロンプトやメンション文面以前にGateway認可で発言が弾かれていた。
- 対応: Sora VPSで `/root/.hermes/.env` をバックアップし、`DISCORD_ALLOW_ALL_USERS=true` を追加。`sora-hermes` tmux sessionを再起動し、`Connected as Sora-VPS2#5856` / `Gateway running with 1 platform(s)` を確認。実プロセス環境で `DISCORD_ALLOW_ALL_USERS=true` と `DISCORD_ALLOW_BOTS=mentions` を確認済み。
- 次回どう防ぐか: Soraが「反応しない」場合、まず `ssh sora 'tail -n 220 /root/.hermes/logs/sora-hermes-gateway.log'` で `Unauthorized user` の有無を見る。見つかった場合はSoraへの会話指示ではなく、Gateway認可設定と再起動を優先する。
- ルール反映: Soraは `require_mention` / `thread_require_mention` 維持のまま、Discord上では誰からのメンションでも認可される。無差別応答ではなく、メンション時のみ動く運用。
