## Threads watcher screenshot gap — 21:35 JST
- Yakonさんから「スクショがない / 過去分も集めて / 最新投稿が取れていない」と指摘。
- 原因: `watcher.py` が Threads プロフィールの `domcontentloaded` 直後に `a[href*='/post/']` を1回読むだけで、SPA hydration完了前の部分DOM（4〜6件）を `ok` として記録していた。
- 対応:
  - `_collect_post_ids_until_stable()` を追加し、描画が安定するまで投稿リンクを複数回サンプリング。
  - 過去最大 `found_count` より少ない取得は今後 `partial_error` として記録するよう修正。
  - テスト対象 `@pocchi_peach` を取得し直し、公開画面で見えている15件をバックフィル。
  - `@hal.lifedesign` はDB 19件 / PNG 19件、`@pocchi_peach` はDB 15件 / PNG 15件までローカル収集済み。
  - `artifacts/threads-watcher-20260517/` に `REPORT.md`, `manifest.csv`, `summary.json`, 全PNG、profile fullpage PNGを作成。
  - Discordへ `threads-watcher-20260517-screenshots.pdf`（36p: 投稿34件 + profile 2件）を添付。zipはDiscord添付制限で弾かれた。
- 検証: `pytest -q` で 34 passed。修正後の live check は `@pocchi_peach found=15 new=0`, `@hal.lifedesign found=15 new=0`。
- 教訓: 件数監視では `found/new/status=ok` だけでなく、スクショ実体・manifest・取得件数低下の異常扱いまでセットで報告する。部分取得を正常扱いしない。
