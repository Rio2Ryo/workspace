## ontrust / gohanai 復旧
- 何が起きたか: `#email-manager引き継ぎ調査` で ontrust が反応せず、gohanai の tmux feed も `localhost:3036 connection refused` になっていた。
- なぜ起きたか: Azure NSG のSSH許可元が古いIP `217.178.131.245/32` のみで、現在の出口IP `130.62.10.199` から入れなかった。さらに gohanai 側 tmux feed は `3034` 起動で、Shiro側Cloudflare tunnelが期待する `localhost:3036` へのoriginが空だった。OpenClaw gatewayもDiscord websocket close後に不安定で、fallback先頭が未設定の `anthropic-vertex/claude-opus-4-6` になっていた。
- 対応: NSGに現在IP用SSH許可 `allow-ssh-shiro-current-20260606` を追加。gohanaiへSSH復旧後、`~/.openclaw/openclaw.json` をバックアップして primary model を `openai-codex/gpt-5.4`、fallbackを `openai-codex/gpt-5.5` / `anthropic/claude-sonnet-4-6` に変更。gohanai tmux feedを `3036` で再起動し、Shiro側に `gohanai-feed-forward` SSH tunnelを追加。OpenClaw gatewayを再起動し、Discord bot probe resolved @ontrust、対象チャンネル解決、gateway readyを確認。
- 次回どう防ぐか: `ops/ontrust-gohan-watchdog.sh` と launchd `com.openclaw.ontrust-gohan-watchdog` を追加し、5分ごとに gohanai gateway、remote tmux feed、local SSH forward、公開Cloudflare feedを確認・復旧する。
- 確認: `https://however-onto-spin-arrow.trycloudflare.com/sessions` が6セッションを返し、`email-manager引き継ぎ調査` snapshotも取得成功。watchdogはlaunchd実行で `exit 0`。
